# MTG Scanner (Flutter app)

Phase 1 MVP — offline Android MTG card scanner. See
`../Phase1_Android_MTG_Scanner_Build_Plan.md` for the full spec.

All Dart source under `lib/` and the tests under `test/` are committed. The
Android platform scaffold (gradle wrapper, `MainActivity`, etc.) is **not**
committed — it is generated once with `flutter create`, as below.

## One-time bootstrap (requires the Flutter SDK — Section 0.1)

```bash
cd app

# 1. Generate the Android platform scaffold WITHOUT clobbering lib/ or pubspec.
flutter create --platforms=android --org com.example .

# 2. Apply the manifest edits below (camera permission + a real label).

# 3. Fetch packages.
flutter pub get

# 4. Run on a connected physical device (Section 0.1 step 3).
flutter run
```

`flutter create` will not overwrite existing files (`lib/main.dart`,
`pubspec.yaml`, etc.), so it only fills in the missing `android/` tree.

### Manifest edits

In `android/app/src/main/AndroidManifest.xml`, add the camera permission and
feature inside `<manifest>` (above `<application>`):

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.CAMERA" />
<uses-feature android:name="android.hardware.camera" android:required="true" />
```

`INTERNET` is needed for the first-launch bundle download and lazy card images;
`CAMERA` for the scan screen. The `camera` plugin requires `minSdkVersion 21`;
if `flutter create` set it lower, raise it in `android/app/build.gradle`
(`defaultConfig { minSdkVersion 21 }`).

## Configure the data-bundle URLs

Set the GitHub Release URLs from Section 0.2 in
[`lib/data/config.dart`](lib/data/config.dart):

```dart
static const manifestUrl =
    'https://github.com/<owner>/<repo>/releases/download/data-bundle/manifest.json';
```

The SQLite URL is read from the manifest's `sqlite_url` field, so it does not
need to be hard-coded.

## Tests

```bash
flutter test                          # all tests
flutter test test/phash_parity_test.dart   # the MANDATORY parity test (Section 5.3)
```

The parity test hashes the fixtures in `test/fixtures/` (generated by
`../dataprep/gen_fixtures.py`) with `lib/recognition/phash.dart` and asserts the
64-bit values equal the golden values produced by `dataprep/phash.py`. Gate all
downstream work on this passing (Section 10, step 5).

If parity ever fails, regenerate the shared cosine table and golden values:

```bash
cd ../dataprep
python phash.py --emit-dart-table > ../app/lib/recognition/phash_cos_table.dart
python gen_fixtures.py
```

## Why sqflite instead of drift

Section 2 prefers `drift` but explicitly allows `sqflite` "if simpler". We use
`sqflite` so the repo carries no `build_runner`-generated sources — every line
that ships is reviewable. The read-only bundle DB and the read/write collection
DB are small and need only straightforward queries.
